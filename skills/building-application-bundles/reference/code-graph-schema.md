## 1. File format

`code-graph/code-graph.jsonl` — one canonical JSON object per line (sorted
keys, no whitespace, UTF-8, LF). Line 1 is the `meta` record; then all nodes
sorted by `id`; then all edges sorted by `(src, kind, dst, resolution)`.

```json
{"rec":"meta","schema":"kf-code-graph/1","extractor":"kfbundle.graph@0.1.0","inventory_only":false,
 "toolchain":{"tree-sitter":"0.25.2","tree-sitter-python":"0.25.0",...},
 "source":{"repo":"owner/repo","commit_sha":"…"},
 "options":{"third_party_globs":[…],"generated_globs":[…],"exclude_globs":[…]}}
```

## 2. Node records

| `kind` | `id` | Attributes |
|---|---|---|
| `file` | repo path | `lang`, `bytes`, `lines`; optional `entrypoint` (`next-route`, `cli-main`, `mcp-tool`), `third_party`, `generated`, `large`, `parse_error`; inventory attrs (below) |
| `class`, `function`, `method`, `type` | `path::Qual.name` | `file`, `line`, `end` (1-based) |
| `external` | `ext:<package or module>` | — (placeholder target) |
| `unresolved` | `ref:<name or specifier>` | — (placeholder target, never guessed) |
| `submodule`, `symlink` | repo path | — (never followed) |

Languages parsed with tree-sitter: Python, TypeScript (`.ts .mts .cts .d.ts`),
TSX (`.tsx`), JavaScript (`.js .mjs .cjs .jsx`), Bash (`.sh`, shebang). The
TS and TSX grammars are never swapped.

Structured inventory (no AST): Markdown (`frontmatter_keys`, `okf_type`,
`headings`), YAML (`documents`, `top_keys`, `yaml_kind`/`yaml_id`/…), JSON
(`top_keys`; `package.json` dependencies become `declares` edges), Rego
(`rego_package`, `rules`, `extractor: regex`), Makefile (`targets`,
`extractor: regex`), `requirements*.txt` (`declares` edges).

## 3. Edge records

| `kind` | From → to | `resolution` values |
|---|---|---|
| `defines` | file/class → symbol | — |
| `imports` | file → file / `ext:` / `ref:` | `exact`, `external`, `unresolved`; flags `reexport`, `dynamic` |
| `calls` | symbol or file → symbol / file / `ext:` / `ref:` | `local`, `import-bound`, `name-only` |
| `renders` | component → component (JSX) | same as `calls` |
| `links` | Markdown file → file / `ref:` | `exact`, `basename` (wiki links), `ambiguous`, `unresolved` |
| `declares` | manifest → `ext:` | `external`; `scope` = dependencies / devDependencies / requirements |

Repeated identical edges collapse into one with a `count`. Import-bound calls
to a module carry the called member in `symbol`.

## 4. Honesty contract

- `defines` and `imports` are exact: imports resolve relative paths, index
  files, extension inference (`.js` specifier → `.ts` source), tsconfig
  `paths`/`baseUrl` aliases and Python relative imports.
- `calls` record only what syntax can support: identifiers bound in the file
  (`local`) or by an import (`import-bound`), `self.`/`this.` members, and
  members of imported modules. Anything else is `name-only` to a `ref:`
  placeholder — or not recorded at all (calls through arbitrary receivers
  such as `obj.method()` are not extracted). Calls to language builtins are
  skipped by a fixed list, so graphs do not vary by Python version.
- Files that fail to parse are kept with `parse_error: true`.

## 5. Determinism contract

Same source commit + same options + same toolchain ⇒ byte-identical output.
No wall-clock fields; stable ids; sorted records; canonical JSON. Gate G11
re-runs the extractor at the pinned SHA and requires byte equality, and
compares the stamped toolchain to the base-ref `.github/kf/toolchain.lock`.

## 6. Derived artifacts

- `code-graph/metrics.json` — counts, entry points, parse errors, fan-in /
  fan-out top 15 (hotspots are fan-in/out only; no churn), external
  dependencies top 30. Third-party and generated files are excluded.
- `code-graph/views/modules.md` — directory-level Mermaid view (≤50 nodes,
  ≤150 edges; solid = imports, dotted = document links) plus a table.
- `code-graph/views/dependencies.md` — external dependencies, entry points
  and a fan-in hotspot view.

All three are regenerated by `build_bundle.py graph` and verified by G11.
